# Evidence — robots.txt served vs. repository

Captured 31.08.2026.

## What the repository contains (`public/robots.txt`)

```
# InPlace, https://inplace.digital
#
# Everything is open, on purpose. The audit of 27.08.2026 found the page had no
# robots.txt at all, which meant a crawler asking for one got the SPA fallback:
# HTTP 200 with an HTML document. Google tolerates that by ignoring the
# unparsable lines; it is still the wrong answer to a question about crawling.
#
# The AI crawlers are NOT blocked, by the owner's decision of 27.08.2026. This
# page wants to be quoted by them, and a Disallow here is the one thing that
# would guarantee it is not. g17-crawl asserts that no Disallow appears in this
# file, so a future copy-paste of somebody else's robots.txt fails the build
# rather than quietly closing the door.

User-agent: *
Allow: /

Sitemap: https://inplace.digital/sitemap.xml

# /llms.txt is generated by scripts/build-llms.mjs from the pages in the build.
# Google states it does not read it and that it changes nothing in Search; it is
# published for the smaller answer engines that do, which is the same decision
# as the absent Disallow above.
```

## Disallow count in the served file

$ curl -s https://inplace.digital/robots.txt | grep -c 'Disallow'

$ curl -s https://inplace.digital/robots.txt | grep -c '^Disallow'

Expected after the fix: `0` from the anchored count. The unanchored count will still return 3,
because the repository file discusses the word `Disallow` in its comments — anchor to the line
start when asserting this in a build gate.
