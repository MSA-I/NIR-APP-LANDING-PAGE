# GATES — build 4, `inplace-aui`

Build 3 (`inplace-folio`) was a static HTML page generated by one Node script.
It had already taken the reference's **layout**. What it had not taken was the
reference's **surface**, and that is what the owner said was missing: "הכל נורא
שטוח ובסיסי … ממש לא נותן את הוואו שאני מחפש."

Build 4 keeps build 3's content verbatim and rebuilds the surface on React +
Vite, with a WebGL shader ground in the product's palette, a separate display
typeface, entrance motion on every chapter, and buttons that answer.

Reference read 2026-08-26: <https://www.aui.io>, plus the eleven land-book
captures in `C:\Users\art1\Desktop\New folder`.

The owner's four decisions, 2026-08-26:

1. Move to React, so 21st.dev components land natively.
2. Shader in the product's own palette, not the reference's orange.
3. Whole page, top to bottom.
4. Add a display typeface for headlines; body stays Noto Sans Hebrew.

Gate numbering follows build 3's, so G1 and G5 are absent: G5 was build 3's
figure-apparatus gate and the apparatus was removed by owner instruction on
26.08.2026, before this build started.

Run the ledger:

```bash
node scripts/gates/all.mjs
```

## G3 — the shader is painted in the application's own colours

The owner's note on 26.08.2026 was that the page was not in the application's
colours, and it was right: the first cut used a turquoise (#38b3c0) the product
does not contain. "In the palette family" is not a strong enough test for that,
so the gate now asserts something exact — every colour in the shader is a token
the running application defines, matched against the OKLCH values in
`data/product-tokens.json` and converted here.

It also asserts the pointer code is **gone**. The owner asked for a ground that
does not answer the mouse; the catalogue component ships a cursor branch in the
fragment shader and four window listeners, and a flag can be flipped back by a
re-pull without anybody seeing it in a screenshot.

Two controls: aui.io's own colours must not resolve to product tokens, and the
token table must be non-empty.

    CHECK: node scripts/gates/g3-palette.mjs
    EXPECT: G3 PASS

**MET.** 52 colours defined by the application; the shader uses four of them —
`#0a171d` color-ink, `#003f47` color-action, `#5d9096` color-action-line,
`#e8eef1` color-topbar. No `u_cursor`, no `pointermove`, no cursor branch.

## What a green run does not say

Every gate measures what somebody thought to ask. Three things on this page are
still only judged by eye:

- Whether the shader's composition is good, as opposed to legible and in
  palette. G7 says the text can be read over it; nothing says it is beautiful.
- Whether the motion is paced well. G12 says it stops when asked; nothing says
  0.72s and a 0.055s stagger are the right numbers.
- Whether the phone layout of chapter 01 reads. The film column stops being
  sticky below `lg` and becomes a plate above four blocks, which is a different
  experience from the desktop one, and no gate compares them.

### What round two cost, and what caught it

Three regressions, each caught by a gate rather than by looking:

- **413px of horizontal scroll at 390px.** The colophon's panel was `position:
  static` on phones, which handed its absolutely positioned aurora — 80vw wide,
  centred with a -50% translate — to an ancestor the panel's `overflow: hidden`
  does not clip. G6.
- **A tagline at 1.15:1.** The catalogue's metallic text runs to fully
  transparent, and `color: transparent` alongside it throws away the fallback
  for every browser that cannot clip text to a background. G7.
- **The figures gate reading a table that no longer existed.** Chapter 04 became
  cards and G14 went looking for `tbody tr`, found nothing, and said so. It now
  reads `data-plan-*` attributes, which is a contract rather than a layout.

### What the new textures cost, and what they cost after

The photographic desk and paper are high-frequency, and x264 spends bits on
grain the eye never sees in motion. At the encoder settings the flat-textured
legs used, the same four legs came out **3.3x heavier**: film.mp4 went from
10.0MB to 26.0MB and film-m.mp4 from 4.7MB to 12.3MB. A 26MB hero clip is the
heaviest thing on the page by an order of magnitude, so it was measured rather
than shipped.

Measured on leg 01, 1920x1080, slow preset, from the same frames:

| CRF | leg 01 |
|---|---|
| 21 (the old setting) | 8.05 MB |
| 24 | 4.89 MB |
| **26 (shipped)** | **3.47 MB** |
| 28 | 2.47 MB |

All three are indistinguishable at a 760x420 crop of the nearest sheet: the
paper tooth, the wood figure and the Hebrew set at 30px are identical. 26 on
desktop and 28 on the phone cut. Final: **film.mp4 12.2MB, film-m.mp4 5.1MB** —
within 20% of the flat-textured clip they replaced, with the textures the owner
asked for. No gate measures this; the number was chased because it was in the
commit diff.

### The film's source, and where it lives

`lab/world/world.html` is the scene the film is rendered from — a CSS-3D world,
one camera as a function of t, nine legs. **It is not in this repository.** It
lives in the main checkout's ignored `lab/` directory, which means the film can
be re-rendered on this machine and nowhere else. Re-texturing it in round two
needed the file copied into the worktree by hand.

That is a real risk and it is written down rather than fixed here: committing a
22KB HTML file and two textures would remove it, and the reason not to is only
that `lab/` is where the render pipeline puts its frames.
